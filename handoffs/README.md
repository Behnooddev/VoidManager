# Handoffs

Each phase ends with a handoff document. It records what the phase delivered, what was verified and where, what was not verified, the decisions taken, and what the next phase needs. A handoff is written so that someone who did not work on the phase can continue from it.

| Phase | Document |
| --- | --- |
| 0 | [phase-0.md](phase-0.md) |
| 1 | [phase-1.md](phase-1.md) |

## Status labels

- Designed: described in documentation only.
- Scaffolded: files exist, not complete or not verified.
- Implemented: code exists and does what the specification asks.
- Tested: automated tests cover it and have run.
- Production-ready: tested, reviewed and documented.

## Template

1. Scope
2. Delivered, with a status per item
3. Decisions taken
4. Verification performed, and where it ran
5. Not verified and known risks
6. How to continue
7. Open items
8. Entry criteria for the next phase
9. File map
